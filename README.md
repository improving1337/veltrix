# Veltrix

Исходники распакованы из исходного архива в корень репозитория; архив сохранён.
Для запуска обновлённой версии используйте **этот каталог**, а не старый
`/workspace/veltrix-local`.

## Запуск

Python 3.12:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
umask 077
.venv/bin/python main.py
```

Порт по умолчанию 8080; переопределение: `SERVER_PORT=8081`.
Логин панели: `admin`, пароль находится в `panel_password.txt`.

Готовая сборка интерфейса лежит в `web/assets`. Для локальной пересборки React-экранов:

```sh
npm --prefix frontend ci
npm --prefix frontend run build
```

История Overview и балансов записывается каждые пять минут в
`security/dashboard.json` после запуска обновлённой панели.

Для облачной среды уже подготовлен `/workspace/veltrix-venv`.

## Deploy

- **Вход по номеру**: номер в международном формате → код Telegram → текущий
  пароль 2FA, если требуется. После успешного входа создаются файлы в `Account/`
  и `Session/`. Незавершённый вход действует 10 минут; его можно отменить.
  Перезагрузка страницы не сохраняет код, пароль или токен входа в браузере;
  незавершённый запрос на сервере истечёт автоматически.
- **Загрузка .session**: принимает авторизованную SQLite-сессию Telethon до 15 МБ.
  Файл и автоматически созданный JSON получают одинаковое имя. При совпадении
  имени существующие файлы не перезаписываются. Этот формат не включает tdata
  или StringSession.
- Для входа по номеру и сессий без JSON используются публичные API ID `2040`
  и API hash `b18441a1ff607e10a989891a5462e627`. Если JSON уже существует,
  его настройки сохраняются.

## Автоматическая защита

Включена по умолчанию для всех подключённых аккаунтов; переключатель в Deploy
позволяет приостановить следующие проверки. Отключение переключателя не отменяет
уже выполненные изменения и не восстанавливает завершённые сессии.

1. Если 2FA нет, создаётся случайный пароль. Уже установленный пароль не меняется.
2. Проверяются авторизации Telegram. Если сессия одна и она текущая, ничего
   завершать не нужно. Если их несколько, завершаются **все остальные** сессии,
   в том числе используемые на других устройствах. Результат повторно проверяется
   через Telegram; успешным считается только одна сессия с признаком `current`.
3. Следующая проверка — через 24 часа. При запрете Telegram для новой сессии
   повтор также через 24 часа; более длинный FloodWait учитывается. Сроки
   сохраняются в `security/state.json` и переживают перезапуск. При остановленной
   панели проверка будет выполнена после следующего запуска и подключения аккаунта.

Если один Telegram ID добавлен в панель несколько раз, автоматическая защита
пропускает его, чтобы сессии панели не завершали друг друга. Удалите лишние записи.

Пароли находятся **на хостинге** в `security/passwords.json`:

```json
{
  "имя_аккаунта": "сгенерированный_пароль"
}
```

Каталог закрыт правами `0700`, JSON-файлы — `0600`. Пароли не возвращаются API,
не показываются в интерфейсе и не выводятся в журнал. JSON хранится без шифрования,
поэтому доступ к нему следует предоставлять только администратору хостинга.
`pending_passwords.json` хранит кандидаты до подтверждения Telegram;
`password_index.json` связывает сохранённые пароли с Telegram ID для восстановления
после сбоев. Не удаляйте эти файлы при перезапуске. Если операция завершилась
таймаутом, кандидат сохраняется и проверяется при следующей попытке. Удаление
аккаунта из панели не удаляет резервную запись его пароля.

Не публикуйте `Account/`, `Session/`, `security/`, `.env` и `panel_password.txt`.
Эти пути исключены из Git. Резервное копирование и перенос на хостинг должны
сохранять их конфиденциальность и права доступа. Панель использует HTTP Basic:
для доступа через Интернет нужен HTTPS перед приложением.

## Планирование услуг

В форме создания заказа доступны:

- **Max** рядом с количеством: проверяет доступный пул для выбранной услуги,
  ссылки, уникальности и свежести. Сначала заполните ссылку. Проверка не запускает
  действия и не резервирует аккаунты; при построении плана пул проверяется заново.
- **Свежесть аккаунтов**: исключает аккаунты, у которых дата последней аватарки
  Telegram находится в последних N днях. Например, при N=7 на 17.11.2026 аватарка
  от 15.11 исключается, от 09.11 — подходит. Аккаунты без аватарки допускаются;
  при ошибке чтения истории аккаунт исключается. Значение 0 отключает фильтр.
- **Время последнего аккаунта (МСК)**: вместо задержек задайте дату и время.
  Интервалы отличаются от среднего на 10–40%, но суммарно точно укладываются
  в оставшееся время. Для одного аккаунта интервал равен всему оставшемуся времени.
  При подтверждении и исключении аккаунта расписание пересчитывается с сохранением
  конечного времени. План с истёкшим временем запустить нельзя. Задержки считаются
  по абсолютным меткам, чтобы длительность предыдущих запросов не прибавлялась
  к каждому интервалу. Это время начала действия последнего аккаунта; сетевые
  задержки, долгие предыдущие операции и ограничения Telegram могут сдвинуть
  фактическое выполнение.

В автоматическом режиме половина квоты первого часа распределяется до 30-й
секунды **от публикации** (не от запуска панели); нечётная половина округляется
вверх. Для 100 просмотров и 34% на первый час это 17 просмотров за первые 30 секунд
и ещё 17 в оставшуюся часть часа. Для реакций используется тот же алгоритм.
Новые посты проверяются каждые 10 секунд, готовые действия — каждые 0,5 секунды;
замеры активных постов выполняются не чаще одного раза в 10 минут для каждого
поста. Поиск новых публикаций продолжается с интервалом 10 секунд. Старые действия не повторяются при
обновлении расписания. Если пост обнаружен или рекомендации реакций готовы позже
30-й секунды, всплеска задним числом нет: действия распределяются на оставшееся
время. Скорость сети, анализ рекомендаций и ограничения Telegram могут помешать
выполнить весь ранний объём в первые 30 секунд.

Строки состояния 2FA убраны из списка аккаунтов и Deploy; информация о защите
остаётся в открытом профиле аккаунта.

## Проверки

```sh
/workspace/veltrix-venv/bin/python -m unittest -v test_account_security test_account_deploy test_account_import test_planning
```

Тесты используют временные каталоги и имитацию ответов Telegram, не подключают
реальные аккаунты и не завершают реальные сессии. `test.py` из исходного архива —
интерактивный Telegram-скрипт, а не часть набора тестов.

Импорт по ссылкам Google Drive/MEGA и распаковка RAR остаются дополнительными
возможностями: для них нужны отдельные пакеты `gdown`, `mega.py` и системный
инструмент распаковки RAR соответственно.

## Вкладка 2FA: независимые сессии

Таблица показывает номер (либо имя файла, пока номер неизвестен), сохранённый
панелью пароль 2FA с кнопкой раскрытия, дату текущей авторизации Telegram,
происхождение и дату первого учёта сессии панелью. Время отображается по МСК.
Для файлов, добавленных до появления реестра, дата учёта не является исторической
датой импорта: она фиксируется при первом просмотре новой вкладки.

Зелёный индикатор означает подключённую сессию, созданную этой панелью;
оранжевый — подключённую импортированную, красный — неподключённую. Красный
индикатор может означать временную сетевую ошибку, а не обязательно отзыв ключа.
Сессии без записи происхождения считаются внешними. Признак «своя» связан
с отпечатком ключа авторизации; подмена файла не сохраняет этот признак.

Кнопка перевыпуска последовательно обрабатывает подключённые внешние аккаунты.
Панель узнаёт номер через исходный клиент, запрашивает новый код новым клиентом,
ожидает только новое сообщение 777000 после своего запроса и создаёт независимую
авторизацию. Код и пароль не выводятся в журналы. Если доставка идёт не через
Telegram либо за 90 секунд код не получен, исходная сессия остаётся без изменений;
используйте обычный вход в Deploy. При неизвестном/неверном текущем пароле 2FA
появляется поле его ввода в таблице. Запрос ожидает пароль до 10 минут.

Новая сессия сохраняется отдельно, повторно подключается, проверяется Telegram ID
и независимость ключа. Только после этого исходные файлы перемещаются в закрытый
`security/retired/`, а исходный клиент отключается локально. Перемещение файлов
**не отзывает** авторизацию в Telegram. Её и другие авторизации отзывает фоновая
защита через новый клиент, соблюдая ограничения Telegram и повтор через 24 часа.
Если фоновая защита приостановлена, таблица сообщает об этом — включите её в Deploy.
На время незавершённого перевыпуска защита исходного клиента приостанавливается,
чтобы он не отозвал новую авторизацию. После перезапуска незавершённый вход
не продолжается автоматически; подтверждённая новая сессия и реестр сохраняются.

Содержимое таблицы 2FA доступно только после входа в панель и отдаётся с no-store.
Для доступа к панели через Интернет используйте HTTPS. Закрытые резервные копии
в retired содержат старые ключи до их отзыва; не публикуйте каталог security.
Дополнительные тесты: `python -m unittest -v test_session_admin`.

В каждой строке 2FA есть кнопка «Перевыпустить сессию» для обработки только
выбранного аккаунта. Используется отдельный endpoint reissue-one: отсутствующее,
пустое или неизвестное имя не запускает массовую обработку. При работающем
перевыпуске второй запуск отклоняется. Для своих/неподключённых сессий и
незавершённого ввода пароля кнопка недоступна. Общая кнопка сверху по-прежнему
обрабатывает все подключённые внешние аккаунты.

## Экран профиля и свежая проверка авторизаций

Профиль открывается на всю ширину рабочего поля. Кнопка «Назад» и Esc возвращают
в список. Данные, приватность, фото/музыка и безопасность разделены по блокам.
В списке Profiles колонка био заменена на число авторизаций последней проверки;
цвет обозначает происхождение сессии/состояние подключения, как в таблице 2FA,
а не отсутствие других устройств. Неизвестное число отображается прочерком.

В профиле кнопка «Обновить сессии» запрашивает GetAuthorizations у Telegram,
показывает число, список устройств и время проверки по МСК. Это отдельная
операция чтения: она не включает/меняет 2FA, не отзывает авторизации и не
переносит срок автоматического повтора. Если Telegram недоступен, отображается
ошибка; прошлое число не выдаётся за свежий результат. Статус «своя» определяется
реестром происхождения и отпечатком ключа, а не догадкой по устройству Telegram.
Пароль показывается по нажатию, поле имеет фиксированную ширину и прокрутку текста.
Таблица 2FA имеет компактную панель действий и фиксированные колонки, поэтому
раскрытие длинного пароля не меняет её размеры. На узких экранах таблица
прокручивается внутри своего контейнера.

На широких экранах (от 1250 px) профиль использует три колонки в пределах
высоты рабочего поля: аккаунт/приватность/управление, данные профиля,
сессии/фото/музыка. Основные поля не требуют прокрутки страницы; длинные списки
и содержимое медиа прокручиваются внутри карточек. На узких экранах сохраняется
вертикальная раскладка. Проверены размеры 1920×990, 1440×900 и 1366×768.

## Настройки автопилота по каналам

- Поиск новых публикаций — каждые 10 секунд после завершения предыдущей проверки.
  Начальный замер выполняется при обнаружении поста, последующие — через 600 секунд
  от последнего замера этого поста. Медленный ответ API может увеличить интервал.
- В общем списке показываются все активные посты и два последних завершённых
  среди всех каналов; в деталях канала — его активные и два последних завершённых.
  Сохранённая история и журналы действий при этом не удаляются.
- Для каждого нового поста случайно выбирается цель до установленного лимита
  реакций. Например, при лимите 15 это 12–15. Цель сохраняется на посте между
  перезапусками. Нехватка уникальных подключённых аккаунтов может её ограничить.
  Ошибки Telegram учитываются в истории выполнения. DeepSeek нужен для
  анализа обычных новостей.
- В каждом канале через «Реакции / промпт» выбираются разрешённые эмодзи и
  редакционные инструкции. Разрешённое ❤️ получает минимум 40% плана, а в
  голосовании, где оно указано среди вариантов, получает большинство. Остаток
  в голосованиях распределяется между доступными вариантами из поста.
  В обычных новостях дополнительные 🔥 ограничены 10%. Выбранные реакции должны
  быть доступны в самом Telegram-канале.
- Для просмотров базовое число получает разброс ±10%: при 40 это 36–44,
  ограниченные количеством доступных уникальных аккаунтов. Для небольших чисел
  диапазон сужается до целых значений (округление границ внутрь диапазона). Цель
  сохраняется на посте и не меняется при обновлении страницы или перезапуске.
  Изменение базовой настройки применяется к новым постам.
- Время действий распределяется со случайным смещением внутри временных участков;
  правило половины первого часа в первые 30 секунд от публикации сохраняется.
  Успех или выполнение до точной секунды не гарантируются: влияют Telegram,
  сеть, доступность аккаунтов и время анализа.
- После смены имени сессии не начатые задания следуют за тем же Telegram ID.
  Уже выполненные/неоднозначные запросы остаются в журнале и не дублируются.

Проверки: `python -m unittest -v test_autopilot` (временные хранилища и имитация API).
После замены файлов перезапустите приложение и обновите страницу браузера.

## CS3BET: массовое распределение игровых монет

Функция предназначена для описанной пользователем игры с бесплатными виртуальными
монетами без денежной стоимости. Путь: CS3BET → Шаблоны → Массовая ставка.

Цель — максимальный потенциальный баланс на одном аккаунте: каждому купону
подбираются свои набор и число матчей, коэффициент стремится к 30 снизу.
Ровно 30 не обещается: используются только существующие коэффициенты.
Купон с наибольшим найденным коэффициентом получает самый большой баланс.
Оставшиеся аккаунты получают купоны по убыванию коэффициента, затем по кругу.

Для 2–12 выбранных открытых матчей перебираются все допустимые купоны с минимум
двумя событиями и коэффициентом ≤30. Число вариантов — от 4 до 64; аккаунтов —
до 1000. Перебор ограничен 100000 допустимых купонов; при превышении требуется
уменьшить набор матчей. Это ограничение вычислений, а не скрытое усечение поиска.

Сначала сохраняется лучший купон, затем подбирается покрытие и добавляются
высококоэффициентные варианты в пределах бюджета. Используются жадный подбор
покрытия и проверка полного фиксированного набора в качестве альтернативы,
чтобы не ухудшать нижний порог без необходимости. Глобальная оптимальность
портфеля по всем возможным сочетаниям купонов не гарантируется. Если найденный
пиковый купон не удаётся совместить с полным покрытием, план не запускается:
нужно больше вариантов/аккаунтов либо меньше выбранных матчей.

Покрытие проверяется по всем 2^N полным бинарным исходам выбранных допустимых
матчей. У купонов могут быть разные наборы событий, поэтому они могут выигрывать
одновременно. Для каждого исхода отдельно рассчитываются суммы выплат и
крупнейший баланс. Покрытие не означает прибыль: концентрация выигрыша на
некоторых аккаунтах может существенно уменьшить общий банк.

Предпросмотр показывает лучший доступный/запланированный коэффициент, число
проверенных сценариев, состав каждого купона, суммы, остатки, диапазоны
крупнейшего баланса и общего банка. Матчи с закрытыми/неизвестными условиями
перечисляются как исключённые. Расчёт предполагает два взаимоисключающих исхода
каждого матча, без отмен, возвратов и иных правил игры.

Сумма каждого купона — min(баланс, 50000), минимум 100. Сессии одного Telegram ID
не считаются разными аккаунтами. Нужны хотя бы четыре подключённых аккаунта с
известными балансами от 100; сложный план может потребовать больше. Остатки
сохраняются на соответствующих аккаунтах. Выигрыши разных аккаунтов не объединяются.

Только отдельное подтверждение запускает последовательную отправку. План живёт
10 минут и одноразовый. Балансы предпросмотра берутся из фонового обхода; перед
каждой отправкой заново проверяются баланс, открытость матчей, коэффициенты и
лимиты. Ставка «весь баланс» в старом шаблоне также ограничена 50000, коэффициент — 30.
Ошибки отдельных строк не останавливают остальные аккаунты; неизвестные отправки не повторяются.
Принятые купоны не отменяются; неполное покрытие показывается явно. Остановка
очереди срабатывает после текущего запроса. После перезапуска автопродолжения нет.

Состояние хранится в cs3bet_bulk_job.json. Перед отправкой записывается `sending`;
при прерывании оно считается `unknown`. Такие аккаунты исключаются из следующих
планов через сохраняемый cs3bet_bulk_unknown.json. Не удаляйте эти файлы ради
повтора: сначала проверьте реальную историю игры. Запросы соблюдают существующий
ограничитель API, поэтому большая очередь может выполняться долго.

Тесты: `python -m unittest -v test_cs3bet_bulk`. Реальные ставки при тестировании
не выполняются. После замены файлов перезапустите приложение и обновите страницу.

## CS3BET: реферальный вход и кнопка «Открыть»

Для первого известного игрового входа передаётся параметр `ref_6J74EAKP`
в RequestMainWebView Telegram. Подписанный init_data с этим параметром
передаётся стандартному API авторизации игры. Если Telegram не включил параметр
в init_data, регистрационный запрос не отправляется. После успешной авторизации
в cs3bet_referrals.json сохраняется отметка по Telegram ID — она не зависит
от имени файла .session. Сами токены и подписанные ссылки в этом файле не хранятся.

Аккаунты с известным прежним балансом или отметкой входа считаются существующими
и не получают повторный параметр. Если аккаунт уже зарегистрирован в игре, но
панель об этом не знает, она может передать параметр при первом входе; фактическое
начисление реферала/возможность его изменения определяет игровой сервис.

Рядом с «Шаблон» появилась кнопка «Открыть». Она получает новую персональную
ссылку через выбранный Telegram-клиент и проверяет ID в данных мини-аппа.
Несовпадение ID отменяет открытие. Ответ не кешируется. При блокировке всплывающих
окон нужно разрешить их для панели и нажать кнопку снова.

Обычная веб-страница не создаёт изолированный профиль браузера: cookies и
localStorage внешнего мини-аппа могут разделяться между окнами. Ссылка подписана
для выбранного аккаунта, но применение входа и обработка кеша зависят от самого
приложения. Проверяйте профиль внутри игры; если сервис переиспользует старую
авторизацию, используйте отдельный профиль браузера/изолированное окно.

Зелёные сообщения об успешном получении ежедневной награды и прокрутке колеса
убраны из списка. Автосбор, таймеры и показ ошибок сохраняются.

Тесты: `python -m unittest -v test_cs3bet_webapp`. Реальные игровые регистрации
и открытие ссылок с настоящими учётными данными при проверках не выполнялись.

## Продолжение остановленной массовой очереди CS3BET

Не запускайте новый план вместо остановленного, если нужно сохранить принятое
распределение. Очередь, аккаунты, суммы и купоны уже сохранены в
cs3bet_bulk_job.json. Перед обновлением сделайте отдельную резервную копию этого
файла и cs3bet_bulk_unknown.json (если он есть). Распакуйте исходники поверх
существующего приложения, не удаляя рабочую папку и файлы данных, затем
перезапустите процесс. ZIP не содержит эти JSON и не должен их перезаписывать.
Перезапуск процесса не равен повторному запуску ставок: принятые строки остаются
принятыми, автоматического продолжения при старте нет.

В CS3BET → Шаблоны → Массовая ставка сохранённая очередь показывается снова:

- «Продолжить неотправленные» повторяет только строки error/not_run/skipped
  с прежними купонами и суммами. Проверки свежих цен и баланса сохраняются.
- «Пересчитать неотправленные» только читает актуальные матчи и показывает
  изменения. Исходные направления не меняются, новые события не добавляются;
  если события закрылись либо коэффициент превысил 30, выбирается допустимый
  поднабор исходных событий с коэффициентом как можно выше, максимум 30,
  минимум два события. Суммы ставок не изменяются. При недостаточном текущем
  балансе отправка снова остановится с конкретной причиной.
- Только «Подтвердить пересчёт и продолжить» применяет изменения и возобновляет
  очередь. Пересчёт действует 3 минуты; устаревший или невозможный пересчёт
  не изменяет очередь и не запускает отправку.

Строки ok и unknown никогда не переводятся в очередь повторно. Аккаунты
с неизвестным результатом прошлой отправки требуют ручной проверки игровой
истории. После пересчёта прежние итоговые диапазоны из первоначального
предпросмотра не считаются актуальным прогнозом; неполное выполнение и
неизвестные результаты по-прежнему не подтверждают покрытие.

Теперь сообщения HTTP-ошибок содержат исходную причину (например, изменение
коэффициента или недостаточный баланс), а не только HTTPBadRequest. Для старых
сохранённых строк уже утраченный текст восстановить нельзя; безопасная повторная
проверка неотправленной строки запишет новую точную причину, если проблема осталась.

## Массовая очередь: актуальные коэффициенты и ускорение

В массовой очереди автоматически принимаются текущие коэффициенты при сохранении
исходных событий и направлений, если произведение не больше 30. Условия 2.05 → 2.0
сами по себе больше не вызывают остановку. Обычная одиночная форма сохраняет
строгую проверку изменения цены. При превышении 30 состав не меняется молча: строка
получает ошибку, остальные идут дальше. Для укорочения нужен прежний явный пересчёт.

Работают до трёх работников очереди. Общие данные рынка кешируются на 15 секунд
с объединением одновременных запросов, баланс и лимиты проверяются для каждого
аккаунта отдельно. Окончательные условия определяет игровой сервис; при явном
отказе именно из-за изменения коэффициента возможна одна повторная попытка
с обновлением рынка. Применяется только подтверждённый ответ success=false,
а не отсутствие ответа. Текущие три обработки при нажатии остановки могут завершиться, новые строки не запускаются.
Сетевые ошибки до отправки также имеют один ограниченный
повтор. После отправки при таймауте повтор запрещён. Лимиты запросов, паузы 429
и FloodWait не обходятся; мгновенная постановка всей очереди не гарантируется.

Явный отказ сервиса теперь помечается rejected («Отклонено сервисом») с причиной,
а не автоматически unknown. Такие строки можно продолжить после исправления.
Реально неизвестные ответы сохраняются как unknown с имеющимся текстом ошибки.
Ошибка одного аккаунта не блокирует обработку остальных. Эти правила действуют
в рабочем веб-приложении; библиотечный BulkGame по умолчанию сохраняет
последовательный режим остановки для совместимости.

Если пользователь уже сам поставил нужный купон на аккаунте с unknown, в
остановленной очереди доступна «Ставка сделана вручную». После явного подтверждения
по истории игры строка помечается ok с manual_verified и датой. Никаких запросов
постановки ставки эта кнопка не делает. Отметка означает заявление пользователя,
а не автоматическую сверку истории API. Должны совпадать аккаунт, сумма и исходы.
Такой аккаунт затем не повторяется при продолжении сохранённой очереди.

Перед обновлением сохраните cs3bet_bulk_job.json и cs3bet_bulk_unknown.json;
распакуйте код поверх, не удаляя файлы данных, и перезапустите приложение.

## VPN

Во вкладке VPN кнопка «Получить ссылку» использует подключённый аккаунт и выполняет шаги, заданные в настройках вкладки. После получения ссылку можно скопировать, скрыть или отправить на почту. В журнале хранится дата получения и срок в 31 день. Исключение скрывает запись из таблицы, а Telegram ID остаётся в истории использования.

### Отправка через Gmail API

1. Включите Gmail API в проекте Google Cloud. [Gmail API](https://console.cloud.google.com/apis/library/gmail.googleapis.com)
2. В Google Auth Platform настройте экран согласия. Для личного Gmail выберите аудиторию External. В режиме Testing добавьте свой Gmail в Test users. В Data Access добавьте область `https://www.googleapis.com/auth/gmail.send`. [Google Auth Platform](https://console.cloud.google.com/auth/overview)
3. Создайте OAuth-клиент типа Desktop app и скачайте его JSON. [OAuth-клиенты](https://console.cloud.google.com/auth/clients)
4. На компьютере с браузером запустите команду из папки проекта, указав путь к скачанному JSON. Войдите в Gmail, с которого будут уходить письма, и подтвердите доступ.

   ```sh
   python gmail_oauth_setup.py "/путь/к/client_secret_….json"
   ```

5. Откройте «Настройки» → «Отправка VPN-ссылок через Gmail» в Veltrix. Выберите Gmail API (HTTPS), введите адрес Gmail и перенесите `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET` и `GMAIL_REFRESH_TOKEN` из локального файла `gmail-credentials.env` в соответствующие поля. Сохраните. Следующее письмо уйдёт с новыми настройками без перезапуска панели.

Хостингу нужен исходящий HTTPS на порту 443 к `oauth2.googleapis.com` и `gmail.googleapis.com`. В режиме Testing для внешней аудитории Refresh Token с доступом `gmail.send` действует 7 дней, затем нужно повторить вход и заменить токен. Храните JSON OAuth-клиента и файл с токеном в закрытом месте. [Срок действия Refresh Token](https://developers.google.com/identity/protocols/oauth2#expiration)

Если нужен SMTP, выберите его в том же разделе. Для SMTP действуют прежние переменные `GMAIL_EMAIL`, `GMAIL_APP_PASSWORD` и `GMAIL_SMTP_PORT` в `.env`, пока соответствующие поля не сохранены в панели. Порт 465 использует TLS, порт 587 использует STARTTLS.

Панель хранит настройки почты в `security/gmail.json`. При обновлении проекта сохраните каталог `security/`, в котором также находится журнал VPN `vpn.json`.

## Сценарии

Вкладка «Сценарии» позволяет собрать последовательность действий Veltrix. Выбери параметры и построй предпросмотр. Подтверждение запускает именно показанный план. Одновременно может выполняться один сценарий. Время запуска и пропуска вводится по МСК. Журнал доступен справа.

```python
accounts = all - [6632326105]

for acc in accounts:
    views(acc, param("post"), unique=True)
    sub(acc, "@example", unique=True)
    wait(10, 15)
```

`all` выбирает подключённые аккаунты. Для постоянной выборки сохрани группу по Telegram ID и используй `group("Основные")`. Команда также принимает ID напрямую, например `views(account=123456789, post="t.me/channel/1")`. Параметры задаются объектом JSON, например `{"post":"https://t.me/channel/1"}`. В редакторе можно сохранить шаблон кода. Ссылки и текст в сценарии пишутся в кавычках.

В справке вкладки доступны сигнатуры всех команд. `poll` принимает номер варианта с единицы или строковый ID варианта. `button` нажимает первую кнопку под постом. `send` принимает `@username` или `me`, а `repost` пересылает в «Избранное». Поддерживаются присваивания и один уровень циклов. Произвольные Python-импорты и выполнение кода запрещены.

Для `sub` и `unsub` флаг `unique=True` проверяет подписку. Для остальных действий с целью он опирается на журнал успешных шагов сценариев. Просмотры вне вкладки «Сценарии» в этот журнал не попадают. Если панель перезапустится во время запроса, шаг потребует ручной проверки. В настройках запуска можно включить паузу после ошибки. `FloodWait` откладывает повтор на срок, заданный Telegram.

Группы, шаблоны, текущий запуск и журнал уникальности сохраняются в `security/scenarios.json`. При обновлении панели сохраняй каталог `security/`.

### График просмотров Автопилота

В режиме «Реалистик» просмотры новых постов планируются на 48 часов. В деталях канала можно настроить активность для каждого часа по МСК и долю просмотров на вторые сутки (по умолчанию 10%). Для поздних публикаций график плавно усиливает утреннюю волну около 08:30. Её время и ширина варьируются между постами. Плавный разброс формы ±7% перераспределяет просмотры внутри суток. Общая цель по просмотрам по-прежнему рассчитывается с учётом настроек панели и доступных аккаунтов.

В предпросмотре можно указать время публикации и число просмотров. Он использует настройки из формы, в том числе несохранённые правки. Каждое построение показывает один возможный вариант. Для обнаруженного поста кривая и настройки сохраняются отдельно, включая перезапуск панели. Старые планы и расписания реакций используют своё 24-часовое окно.

В списке каналов у каждого канала есть переключатель графика. **Легаси** выбран по умолчанию и использует прежнее распределение по 24 часам после публикации. **Реалистик** включает 48-часовое распределение по МСК. Смена режима применяется к новым постам.

Автопилот оценивает публикацию для репостов вместе с анализом реакций. Обычные новости получают цель около 2–3% от запланированных просмотров. Заметные события, изменения с последствиями и розыгрыши получают больше, до 10%. Если оценка ИИ недоступна, используется локальная оценка текста. Число репостов округляется до целого с верхним пределом в 10%. При автоматическом выполнении репосты отправляются в «Избранное» и учитывают настройку «Только подписчики».

### Опросы в Автопилоте

Для новых встроенных опросов Telegram DeepSeek получает вопрос, текст поста и пронумерованные варианты. Автопилот один раз выбирает долю в пределах 40–60% от целевых просмотров и распределяет целое число голосов по весам вариантов. Голосует часть аккаунтов из плана просмотров, по одному варианту на аккаунт. Голоса выполняются в первые 24 часа после публикации и только до закрытия опроса. План и результаты по вариантам видны в карточке поста и сохраняются между перезапусками.

Просмотры и реакции для опроса берутся из настроек канала. Если DeepSeek недоступен, расписание просмотров и подбор реакций продолжаются, а голосование ждёт оценки вариантов.

### Метки аккаунтов

Метка видна в таблице Profiles и меняется в профиле. У сессий одного Telegram ID общая метка. «Общий» доступен обычным услугам и Автопилоту. «Автопилот» резервирует аккаунт для Автопилота и явного выбора в сценарии. Массовые услуги подбирают только аккаунты с меткой «Общий».

В разделе «Загрузка» можно включить метку «Автопилот» для следующих добавленных аккаунтов. Галочка сохраняется, а существующие метки меняются через профиль. Метки хранятся в `security/account_flags.json`.

В сценариях `all` включает аккаунты с меткой «Общий». Выбрать зарезервированные аккаунты можно так:

```python
for acc in accounts(flag=autopilot):
    sub(acc, "https://t.me/cs2lab", unique=True)
```

### Просмотры после подписки

После успешного вступления в канал панель пытается добавить просмотр последней публикации. При наличии предыдущей публикации она также получает просмотр с вероятностью 50%. Ошибка просмотра не меняет результат подписки.

### Фото во «Входящих» и сценариях

В открытом чате нажми «Фото» или вставь изображение из буфера обмена в поле сообщения. Текст в поле станет подписью.

В редакторе сценариев нажми «Прикрепить фото» или вставь изображение через Ctrl+V. Используй `photo()` в вызове `send_photo`. Предпросмотр фиксирует случайную выборку аккаунтов. После подтверждения прикреплённое фото доступно сценарию и при перезапуске панели.

```python
for acc in random_accounts(all, 10):
    start(acc, "https://t.me/examplebot?start=abc")
    send_photo(acc, "@examplebot", photo())
    wait(1)
    bot_button(acc, "@examplebot", 1, text="❤️")
```

Номер кнопки считается с единицы по строкам слева направо. После шага `send_photo` или `send` команда `bot_button` ищет последний входящий ответ новее отправленного сообщения. Если бот отвечает с задержкой, панель несколько раз проверяет чат. Для изображения поддерживаются JPEG, PNG и WebP до 10 МБ.
